# Библиотека упражнений

Данные: `core/scenarios/library/exercises.yaml`, схема: `schema.exercise.json`,
загрузчик: `core/scenarios/exercises.py`.

## Зачем отдельный слой

Упражнения лежат отдельно от сценариев по той же причине, по которой сценарии лежат
отдельно от кода: содержание ревьюит врач, а не программист. Этап плана ссылается на
упражнения по `id`, карточки не дублируются по пятнадцати файлам сценариев.

Бот не придумывает дозировки. Валидатор не даст загрузить упражнение без ограничений
(`limits`) и без хотя бы одной из величин: `reps`, `duration_seconds` или `note`.
Нет записи — нет упражнения в плане.

## Карточка

Поля ровно те, что требует ТЗ:

| поле | что это |
|---|---|
| `title` | название |
| `instruction` | понятная инструкция бытовым языком |
| `lookup_hint` | подсказка посмотреть упражнение в интернете; по умолчанию собирается из названия |
| `dosage` | подходы с повторениями **или** длительность, плюс примечание |
| `limits` | ограничения: до какой боли, чего не делать. Обязательны |
| `body_region` | область тела, совпадает с `body_region` сценария |
| `phase` | `acute` → `subacute` → `return` |
| `equipment` | что нужно из домашнего инвентаря |
| `review_status` | `draft` или `approved` |

Отметка выполнения и комментарий в карточке не хранятся — это данные пользователя,
они живут в `plan_item_logs`.

## Статус содержания

**Все 26 упражнений сейчас `review_status: draft`.** Содержание и дозировки написаны
консервативно (амплитуда и изометрия раньше, сила и прыжки позже, без оборудования,
без проверок «на сколько терпит»), но **требуют подписи профильного врача до беты**.

Список черновиков отдаёт `ExerciseLibrary.drafts()`; тест
`tests/scenarios/test_exercise_library.py` фиксирует, что содержание ещё не подписано —
когда врач подтвердит, тест нужно будет поменять вместе с `review_status`.

## Как упражнения попадают в план

`EXERCISES_BY_REGION` в `tools/retier.py` задаёт, какие упражнения идут в какой этап
планов `self_rehab_basic` и `self_rehab_guarded`, по области тела сценария. Вставку
в YAML делает идемпотентный скрипт:

```bash
uv run python -m tools.plan_exercises --dry-run
uv run python -m tools.plan_exercises
```

Этап «снять нагрузку» получает фазу `acute`, этап возвращения нагрузки — `subacute`
и `return`. План `self_rehab_guarded` получает только `acute`: он выдаётся там, где
симптомы стойкие, и наращивать нагрузку самостоятельно там нельзя.

## Правка библиотеки и активные планы

Карточки **вшиваются в снимок плана** в момент выдачи (`core/scenarios/snapshot.py`,
`SNAPSHOT_FORMAT = 2`). Поэтому правка `exercises.yaml` не меняет упражнения тому, кто
уже идёт по программе: он доходит по своей копии. Снимки формата 1 читаются по-прежнему,
просто без упражнений.

## Добавить упражнение

1. Дописать карточку в `exercises.yaml` с `review_status: draft`.
2. Прогнать `uv run pytest tests/scenarios/test_exercise_library.py` — проверится схема,
   обязательность ограничений и согласованность дозировки.
3. Если упражнение должно попадать в планы, добавить его id в `EXERCISES_BY_REGION`
   и прогнать `tools/plan_exercises`.
4. Отдать на ревью врачу; после подтверждения поменять `review_status` на `approved`.
